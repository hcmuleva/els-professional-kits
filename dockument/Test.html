⚙️ Functional Testing (Karate Framework)

Objective

Ensure that all business features of the API are working correctly with automated regression tests.

Goal

  • Automate login, registration, profile, and core APIs.
  • Provide CI-ready test suite.
  • Enable smoke, sanity, regression test categories.

Approach

  • Karate DSL for API automation.
  • Feature files organized by module.
  • Tagged execution for selective runs.

Tools & Tech Stack

  • Karate – API automation
  • Java + Maven – Build system
  • JUnit / TestNG – Runners
  • Allure – Reporting

Sample Runner

package strapi.auth;

import com.intuit.karate.junit5.Karate;

public class AuthRunner {
    @Karate.Test
    Karate testAuth() {
        return Karate.run("login").relativeTo(getClass());
    }
    @Karate.Test
    Karate testLogin() {
        return Karate.run("login").tags("@smoke").relativeTo(getClass());
    }
}

Execution

# Run all tests
mvn test

# Run by tag
mvn test -Dkarate.options="--tags @smoke"

🚀 Performance Testing (K6 Framework)

Objective

Measure system scalability and stability under real-world traffic conditions.

Goal

  • Identify performance bottlenecks.
  • Define performance SLAs (Response Time, Throughput, Error Rate).
  • Validate system reliability under load and stress.

Approach

  • Use K6 for load, stress, soak testing.
  • Scenarios designed as Level 1, 2, 3 progression.
  • Data-driven login and multi-scenario tests.

Quick Commands

# Install K6
brew install k6      # macOS
choco install k6     # Windows
sudo apt-get install k6  # Linux

# Run tests
k6 run performance/level1-basic.js
k6 run performance/level2-datadriven.js
k6 run performance/level3-advanced.js

Three Levels

LevelVUsDurationRPSScenariosGoal
1102m2–51Learn basics
2505m6–153Data-driven
320017m10–504Production scale

Thresholds

Level 1: Response Time (p95) < 500ms | Error Rate < 1%
Level 2: Response Time (p95) < 800ms | Error Rate < 2%
Level 3: Response Time (p95) < 1000ms | Error Rate < 5%

Metrics

  • http_req_duration – Total request time
  • http_req_failed – Error ratio
  • vus – Virtual users
  • checks – Assertion pass rate

🔐 Security Testing + CI/CD Integration

Objective

Integrate SAST, DAST, and Dependency Scanning into CI pipelines for full coverage.

CI/CD Tools

  • GitHub Actions, Jenkins, GitLab CI for pipelines
  • SonarQube – Code quality & coverage (SAST)
  • OWASP ZAP – Runtime vulnerability scanning (DAST)
  • Mend / Checkmarx – Dependency scanning

CI Levels

  • Unit Tests – run on PRs
  • Coverage Checks – enforce min %
  • SAST – static code analysis
  • DAST – dynamic runtime scan
  • Performance Smoke – run nightly

Sample GitHub Workflow

name: CI Pipeline
on: [push, pull_request]
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Setup JDK
        uses: actions/setup-java@v3
        with:
          java-version: '17'
      - name: Run Functional Tests
        run: mvn test
      - name: Run K6 Smoke Test
        run: k6 run performance/level1-basic.js
      - name: SonarQube Analysis
        run: mvn sonar:sonar
